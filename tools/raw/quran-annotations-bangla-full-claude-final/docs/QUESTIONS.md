## What each answer can and cannot tell you

**Q01** (`q01_word_meaning.py`): Only a word-level gloss from the Treebank exists (on 77,915 segments). There is no contextual translation or lexicon entry in the data.

**Q02** (`q02_root_lemma_pos.py`): Prefixes, pronoun suffixes and many particles have no root or lemma in the source. The root/lemma meaning is not part of the data.

**Q03** (`q03_word_construction.py`): Segment text is Uthmani spelling, so segments cannot be marked on the IndoPak letters themselves.

**Q04** (`q04_word_features.py`): Features exist only where the Treebank annotates them (for example case only on nouns). Mood descriptions use the corrected English text.

**Q05** (`q05_verb_form.py`): Form I is never written in the source: an unmarked verb is inferred to be Form I (the default in the feature guide). Nouns that carry a form annotation are listed separately and are not verbs.

**Q06** (`q06_phrase_membership.py`): Only the constituents the Treebank marks (NS, VS, CS, PP, SC, S) are available; idafa and adjective-noun phrases are visible through the relations (see Q07, Q15), not as constituents.

**Q07** (`q07_word_relations.py`): Relation labels are the Treebank's own; a word with several segments has one relation per segment. The head of a root or NonRel node is the node itself.

**Q08** (`q08_case_explanation.py`): The source has the case, the relation and the head but no explanation text. The "reason" is a rule applied by this project to those three annotations (grammar_data.CASE_RULES); a case/relation pair without a rule returns no reason instead of a guess.

**Q09** (`q09_sentence_boundaries.py`): Boundaries are the Treebank's sentence ids (which are syntactic units, not punctuation). 26 sentences are prefix-only fragments that own no written word.

**Q10** (`q10_sentence_elements.py`): Relation labels are the Treebank's (Subj, Pred, Obj, Poss, Adj, link, gen, ...); implicit elements are included and marked.

**Q11** (`q11_dependency_tree.py`): The tree is the Treebank's head-dependent structure at segment level; NonRel prefixes are listed apart because they point to themselves.

**Q12** (`q12_implicit_elements.py`): Only the 11,157 implicit nodes the Treebank annotates (unwritten subjects, verbs, pronouns). They have no IndoPak word; the anchor says between which written words they sit.

**Q13** (`q13_particles_in_sentence.py`): The data lists every particle with its POS and syntactic relation and gives the word order as POS and function sequences. It does NOT say what a particle does to the meaning.

**Q14** (`q14_frequencies.py`): Counts segments (lemma, root, pos, particle) or whole words (function); no frequency weighting by surah or length.

**Q15** (`q15_examples_of_construction.py`): A construction is found by relation label (e.g. Poss = idafa possessor, Adj = adjective) or by a POS / function sequence inside one sentence; nothing is ranked by pedagogical value.

**Q16** (`q16_verb_form_statistics.py`): Counts verbs only (POS V). Form I is inferred for every unmarked verb. Nouns carrying a form annotation are excluded.

**Q17** (`q17_derived_nouns.py`): Counts nouns and adjectives annotated as ACT_PCPL / PASS_PCPL / VN; they are never counted as verbs.

**Q18** (`q18_repeated_sequences.py`): Reads the sequence annotation JSON written by stage 04 (default projections: all-segment POS, function without NonRel). Never crosses sentence boundaries.

**Q19** (`q19_occurrences.py`): Root and lemma are Buckwalter strings as in the Treebank; --text searches the normalized (unvocalised) spelling.

**Q20** (`q20_source_issues.py`): Lists what the validation found; nothing is corrected silently.

**Q21** (`q21_root_family.py`): Root and meaning labels come from the Treebank; the gloss is a short word-level label. Words without a root are not included.

**Q22** (`q22_verb_patterns.py`): Counts the Treebank relations around each occurrence. "Object" includes a quoted statement after "said". A verb can have several categories in one use.

**Q23** (`q23_ayah_vocabulary.py`): Frequency is counted over the whole Quran by dictionary word (lemma); pronouns and some particles have no lemma and are not counted.

## What the data cannot answer

* *Why* a case applies: the source has case, relation and head but no explanation text. Q08 applies a small documented rule table (`pipeline/lib/grammar_data.py`, `CASE_RULES`) and returns nothing when no rule fits.
* What a particle does to the meaning, and why the word order is what it is: only labels and sequences exist (Q13).
* Contextual meaning: only the word-level gloss exists (Q01).
* A sentence-level "verbal / nominal" label: the Treebank marks constituents (VS, NS, ...) but not the sentence type itself.

## Adding a question

1. Copy any `queries/qNN_*.py`, give it the next number and fill in `QUESTION`, `KIND`, `LIMITS`, `ARGS`, `DEMO`, `CHECK` and `answer()`.
2. Read only through `queries/_common.py` / `pipeline/lib/grammar_data.py` (the two JSON layers). If the field you need is missing, the JSON schema must change, not the query.
3. Run `python3 queries/_self_test.py`, then `python3 pipeline/11_docs.py` to regenerate this page.

## Workflow checkpoint

The pipeline is `01_normalize` -> `02_build_json` -> `03_validate_json` -> `04_generate_csv` -> `05_analysis` -> `06_phrases` -> `07_lexicon_tables` -> `08_syntax_tables` -> `09_reading_tables` -> `10_validate_tables` -> `11_docs` -> `12` query self-test. After stage 03 the JSON is final: **decide the questions you need answered at that point**, add or adjust scripts in `queries/`, and only then rely on the CSV and analysis stages.
