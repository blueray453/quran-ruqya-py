What this dataset enables

Multi‑level tiling

Every word, phrase and clause has exact [start,end] word ranges; phrases tile clauses, clauses tile the ayah. Verified by the build script.

Bilingual alignment

Each phrase carries English and Bangla. Joining phrases in Arabic order yields a natural sentence in both languages — no reordering needed.

Morphology inline

Each word has QUL root/lemma/stem and QAC POS + features + prefix tags, so you can colour by category, filter by root, or count by feature.

Repetition mining

Grouping phrases by a normalised translation_key and clauses the same way reveals repeated formulas (e.g. قُلۡ ×6, هُوَ ٱلَّذِي ×3).

Consistency checking

Same Arabic → same translation_key across the whole surah (0 conflicts). Cross-surah you can flag any word that gets a different phrase context.

Waqf-aware

Pause marks (ۖ ۚ) are preserved. Phrases that end on a waqf mark are natural recitation units; the analysis panel counts them.

Cross-references

Mutashabihat (phrase repetition across the Qur’an) and matching-ayah data live alongside each ayah in mulk.json, so you can show parallel ayahs.

Grammar-aware

Prefix tags distinguish CONJ (و + noun phrase) from REM (resumption و, new clause). Clause boundaries can be mined against these.

Length statistics

Phrase length (1–3 words 98%), clause length (2–6 words 95%) — verified at build time. Useful for ML segmentation models.

Interactive reading

Toggle level, hover any word for morphology, click any node for its translation. Everything is derived directly from data/mulk.json.

Search

Search by Arabic substring, root, or English/Bangla translation — every match is highlighted in place.

Extensible

The same file format scales to 114 surahs; the pipeline (generate_spec.py → build_dataset.py) already produces this shape.
