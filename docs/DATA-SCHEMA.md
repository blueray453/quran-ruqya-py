# DATA-SCHEMA

# Data folder schema

The `.ruqya` file is JSON. The data folder next to it is a **derived artifact**
generated by `tools/fetch_qul.py` from QUL JSON exports. It is not meant to be
edited by hand — regenerating it overwrites your changes — but it *is* the
runtime contract that `DataStore` in `src/ruqya_quran/main.py` reads.

Everything below lives under the playlist's `data_dir` (default `data/`).

---

## Layout

```
<data_dir>/
├── VERSION                          # small JSON: what was bundled
├── meta/
│   └── surahs.json                  # surah names, both scripts
├── script/
│   └── words.json                   # Arabic word-by-word tokens
├── wbw/
│   ├── en.json                      # English word translations
│   └── bn.json                      # Bangla word translations
├── translations/
│   ├── en.sahih.json
│   ├── bn.taisirul.json
│   └── bn.rawai.json
├── recitations/
│   └── <reciter>.json               # segments + duration per ayah
├── audio/
│   └── <reciter>/
│       └── <surah>_<ayah>.mp3       # one file per ayah
└── clips/
    └── ...                          # user-supplied custom audio
```

`VERSION` and everything except `clips/` is regenerated by `tools/fetch_qul.py`.
`clips/` is user-supplied and never touched by the tool.

---

## `VERSION`

```json
{
  "source": "QUL / Tarteel",
  "reciters": ["ar.abdurrahmaansudais", "ar.alafasy", "ar.ghamdi",
               "ar.husary", "ar.husarymuallim", "ar.saoodshuraym"],
  "translations": ["en.sahih", "bn.taisirul", "bn.rawai"],
  "wbw": ["en", "bn"]
}
```

Presence of `VERSION` is the marker `openPlaylist()` uses to decide whether the
data folder looks bundled. Its absence is a warning, not fatal.

---

## `meta/surahs.json`

Top-level keys are **surah numbers as strings** (`"1"` … `"114"`). Values are
metadata dicts. `main.py` reads exactly two keys:

```json
{
  "1": { "name": "Al-Fatihah", "name_arabic": "الفاتحة", "...": "..." },
  "2": { "name": "Al-Baqarah", "name_arabic": "البقرة",  "...": "..." }
}
```

**Fallback:** if `name` is missing, the sidebar shows `surah:ayah` (e.g. `1:1`).
If `name_arabic` is missing, the Arabic title is blank.

---

## `script/words.json`

Keys are `"<surah>:<ayah>:<position>"`, position starting at 1. Values are dicts
with at least `text`:

```json
{
  "1:1:1": { "text": "بِسْمِ", "...": "..." },
  "1:1:2": { "text": "ٱللَّهِ", "...": "..." }
}
```

`DataStore.words(surah, ayah)` walks positions 1, 2, 3, … until a key is
missing — so a gap terminates the ayah. The same positions bound the segment
walk in `recitations/*.json` below.

---

## `wbw/en.json`, `wbw/bn.json`

Same key shape as `script/words.json`; value is a plain string:

```json
{
  "1:1:1": "In (the) name",
  "1:1:2": "of Allah"
}
```

Missing keys render as empty strings — the word still highlights, the meaning
bar just shows only the Arabic for that word.

---

## `translations/<edition>.json`

Keys are `"<surah>:<ayah>"` (no position). Values are **either** a dict with
`t` **or** a bare string — `DataStore.translation()` accepts both:

```json
{
  "1:1": { "t": "In the name of Allah, the Entirely Merciful, ..." },
  "1:2": "All praise is due to Allah, Lord of the worlds."
}
```

If the edition's file is missing entirely, `translationText` is empty.

---

## `recitations/<reciter>.json`

Keys are `"<surah>:<ayah>"`. Values have `segments` (a list of
`[position, start_ms, end_ms]` triples) and optionally `duration` (ms):

```json
{
  "1:1": {
    "segments": [[1, 0, 320], [2, 320, 760], [3, 760, 1200], [4, 1200, 1650]],
    "duration": 2100
  }
}
```

- `segments` positions correspond to `script/words.json` positions.
- `duration` is the audio file's duration in **milliseconds** (probed by
  `mutagen` in `tools/fetch_qul.py`). If absent, the seek bar uses the value
  reported by `QMediaPlayer` once the file starts playing.
- Extra segments beyond the number of words in `script` are silently ignored
  (harmless tokenization drift — see `docs/KNOWN-NON-ISSUES.md`).
- Missing segments render words with no timing highlight but the word is still
  shown and can still be clicked to trigger a mark.

---

## `audio/<reciter>/<surah>_<ayah>.mp3`

Plain MP3 files. Filename is **`{surah}_{ayah}.mp3`**, no zero-padding (i.e.
`1_1.mp3`, not `001_001.mp3`). `DataStore.audio_path()` builds this path
directly; if you download QUL audio in a different layout, rename or override
`DataStore.audio_path()`.

Missing file → the entry is created with `error="audio missing: ..."` and
`play()` refuses it. The reading area still shows Arabic and translation
(they come from JSON, not audio), which is why the app is useful offline even
for ayahs whose audio you haven't downloaded.

---

## Regeneration

```bash
make bundle-fast    # JSON only — fast, validates tokenization
make bundle         # JSON + audio — slow (~2.5 GB), needs tools/raw/
make bundle-sudais  # one reciter only, for smoke tests
```

The tool is resume-safe: `.mp3.part` files are renamed on completion and
resumed via HTTP Range requests. `--validate-only` checks tokenization
alignment without writing anything.
